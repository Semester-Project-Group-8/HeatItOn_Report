\section{Introduction}

\subsection*{Problem Statement}

\hspace*{1cm}HeatItOn is a utility in the city of Heatington that supplies heat to approximately 1600 buildings. HeatItOn currently plans heat production manually, which makes it hard to always choose the cheapest combination of production units. The problem is therefore to develop an optimization system that can automatically create heat production schedules that always meet the heat demand \cite{projectdata} while minimizing total costs and maximizing profit from electricity production/consumption.

\subsection*{Problem Analysis}

\hspace*{1cm}HeatItOn is a utility in the city of Heatington that supplies heat to approximately 1600 buildings through a district heating network. Heat is produced by traditional heat‑only boilers and by units that both produce heat and produce or consume electricity (CHPs). Most of the heat comes from cogeneration plants that use different fuels such as waste, gas, coal, and biomass \cite{lund20144gdh}. 

District heating works by pumping hot water from a plant through insulated pipes to buildings, where it is used for space heating and hot tap water,  then cooled water then flows back to the plant to be reheated. 

Today, HeatItOn plans its heat production manually. This makes it difficult to choose the best combination of units and to react to changing electricity prices in a systematic way. Our task is to develop software that optimizes heat production and creates heat schedules for all available units with the lowest possible costs and the highest possible profit from the electricity market.

System will consist of 5 main modules:
\begin{itemize}
    \item Optimizer (OPT)
    \item Data Visualization (DV)
    \item Asset Manager (AM)
    \item Source Data Manager (SDM)
    \item Result Data Manager (RDM)
\end{itemize}

\textbf{Optimizer (OPT):} \\
The OPT considers all the available production units and calculates the best economical schedule of the heat production while securing heat availability to all buildings at any time. All units have a specific production cost, expressed in DKK per MWh produced heat. The source of this information is excel file called 2026 Heat Production Optimization - Danfoss Deliveries  

\medskip

\textbf{Data Visualization (DV):} \\
The DV is responsible for a graphical presentation of important source and result data.  

\medskip

\textbf{Asset Manager (AM):} \\
The AM is a repository for static system information and is responsible for making this information available for other modules. Through the AM, other modules can retrieve heating grid information such as name and a graphical representation of the grid.  

\medskip

\textbf{Source Data Manager (SDM):} \\
The SDM is a repository for dynamic system information. The SDM can hold its data in local CSV files. The SDM provides time series for the heat demand and electricity prices. Both the heat demand and the electricity prices are given with a resolution of 1 hour.  

\medskip

\textbf{Result Data Manager (RDM):} \\
The RDM is a repository for optimization results 

\subsubsection*{Scenarios}

\textbf{Scenario 1 (Heat only)} \\
\hspace*{1cm}Scenario 1 uses a single district heating network with three gas boilers (GB1, GB2, GB3) and one oil boiler (OB1).  The gas boilers are cheaper, while the oil boiler has higher production costs and is mainly used in peak demand periods. All boilers have constant production costs that do not depend on the hour of operation. Strategy for scenario one is to run the cheapest gas boiler first and then add production from the more expensive boilers if needed to meet the heat demand. There should also be chosen period of 30 to 60 hours when one of the gas boiler will be down due to maintenance. 

\medskip

\textbf{Scenario 2 (Heat and electricity)} \\
\hspace*{1cm}Scenario 2 uses two gas boilers (GB1, GB3), one gas motor (GM1), and one electric boiler (EB1). The gas motor produces electricity (which can be sold), while the electric boiler consumes electricity (which must be bought). When electricity prices are high gas motor has to be running because selling electricity generates extra income. When electricity prices are low electric boiler has to be running because electricity is cheap to buy. 

To decide which units to use in each hour, net production cost will be calculated for each unit and then compared in order to figure out best result. 

\medskip

This project will be using data delivered by Danfoss, including:
\begin{itemize}
    \item Graphical representation of the district heating network
    \item Configuration parameters for each production unit (image, produced heat, produced/consumed electricity, primary energy consumption, production costs, $\text{CO}_2$ emissions)
    \item Heat demand and electricity prices for a 14-day winter period with 1-hour resolution
    \item Heat demand and electricity prices for a 14-day summer period with 1-hour resolution
\end{itemize}

\medskip

If there is time left,  project can be extended by usage of other visualization libraries, storing data in a database, enabling or disabling units directly from the UI, running alternative configurations in Scenario 2, and implementing APIs and an API client for reading electricity prices from Energinet.dk.

\section{Target User Persona}
The system is designed with a specific target audience in mind. To ensure an optimal user experience, the ideal user (persona) interacting with this system is assumed to have the following profile:
\begin{itemize}
    \item Be able to read in English
    \item Be able to navigate a simple UI
    \item Have a basic understanding of the district heating problem being solved by the system
    \item Be able to read and understand basic input/output data
\end{itemize}


\section{System Requirements}
The system is split into three parts: Front End, Back End and the Database. Both the Backend and the Database are run in a Linux Docker container. The Frontend is run locally on the user's machine. For a machine to run the project they need the following:

\subsection*{Software Specifications}
\begin{description}
    \item[Entire project:] .NET 9.0
    \item[Backend:] Docker Desktop (latest version)
    \item[Database:] Docker Desktop with MySql Image (shall be installed automatically if missing)
    \item[Frontend:] Required NuGet packages (all must be compatible with .NET 9.0):
    \begin{itemize}
        \item Avalonia.UI
    \end{itemize}
\end{description}

\subsection*{Hardware Requirements}
Requirements that are necessary to run Docker, as without it a project cannot run.
\begin{multicols}{2}
\begin{itemize}
    \item WSL version 2.1.5 or later (for Windows)
    \item Any of the following OS's: Windows 10/11 (64 bit), MacOS, Linux (64 bit)
    \item 4GB of RAM
    \item Motherboard supporting hardware optimization
    \item 3GB of free space
\end{itemize}
\end{multicols}
